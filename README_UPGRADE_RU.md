# GAB Local OCR v0.4.1

## Что исправлено относительно v0.4.0

- Для слов из PDF и Tesseract сохраняется исходный порядок блоков, строк и слов. Это исправляет перестановку слов внутри адресов, вызванную сортировкой только по микроскопическим различиям координат Y.
- Для страницы 7 добавлена коррекция перспективы по внешнему четырёхугольнику таблицы; координаты слов PDF преобразуются той же матрицей.
- Строки адреса с несколькими почтовыми индексами теперь получают предупреждение `address_contains_multiple_postcodes_check_row_alignment`.
- Необычная длина почтового индекса получает предупреждение `address_postcode_length_unusual_manual_review`.
- Первая строка сканированных страниц 2 и 5, касающаяся верхнего края изображения, помечается `first_row_touches_scan_edge_manual_review`.
- Версия API: `0.4.1`.

## Совместимость

Сохраняется прежний API:
- `GET /health`
- `POST /extract`
- multipart-поле `file`
- заголовок `X-API-Key`

Сохранены поля ответа, используемые текущим n8n:
- `pages[]`
- `pages[].raw_text`
- `pages[].tables[].rows`
- `pages[].tables[].html`

Также доступны `coordinate_rows`, `layout`, `records_detected`, `records_needing_review`, `total_coordinate_rows` и `processing_seconds`.

## Проверка на исходном 8-страничном PDF

- Синтаксис Python: успешно (`py_compile`).
- Страниц: 8.
- Координатных строк: 140 (21, 20, 19, 19, 20, 18, 21, 2).
- Время теста в локальной среде: примерно 23 секунды.
- Для страницы 7 `perspective_rectified=true`.
- В первом столбце страницы 2 распознано название `Сарыч`.
- Адреса страниц с текстовым слоем собираются в порядке строк PDF; на странице 1 адрес первой записи стал `г. Набережные Челны, пр. Набережночелнинский, д. 49`.

## Ограничения, которые остаются видимыми

- Система не должна считать каждый извлечённый текст подтверждённым фактом. В тесте 56 из 140 строк отмечены для ручной проверки по отсутствующим полям, обрезке края, сомнительному индексу, нескольким индексам в одной ячейке или повороту страницы 8.
- На первой строке страницы 2 верхняя часть адресного поля физически обрезана краем исходного скана; отсутствующие пиксели нельзя восстановить гарантированно.
- Страница 8 остаётся повёрнутой и отмечается для ручной проверки.
- Проверяйте `records_needing_review` и `coordinate_rows[].warnings` до передачи данных в Qwen/PostgreSQL.

## Обновление

1. Заменить в основном Git-проекте только `app.py`, `Dockerfile`, `requirements.txt` и этот README.
2. Не добавлять в Git PDF, `.env`, API-токены, экспорт OCR или базу данных.
3. Проверить локально: `python3 -m py_compile app.py`.
4. После Push на сервере создать резервную копию `/opt/gab/app.py`, `/opt/gab/Dockerfile`, `/opt/gab/requirements.txt`.
5. Выполнить `git pull --ff-only` в `/opt/gab`.
6. Проверить `python3 -m py_compile app.py`.
7. Выполнить `docker compose config -q`, затем `docker compose build --no-cache gab_ocr`.
8. Только после успешной сборки выполнить `docker compose up -d --no-deps --force-recreate gab_ocr`.
9. Проверить `/health` из контейнера n8n. Не перезапускать n8n, PostgreSQL или Ollama.

Сервис продолжает использовать `OCR_API_TOKEN` из существующего `/root/ai-stack/.env`.

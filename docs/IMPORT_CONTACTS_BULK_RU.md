# Контакты из DaData/Checko и массовый перенос импорта

В карточке импортированного документа откройте «DaData, Checko и массовый перенос». Работа с реестрами и создание карточек — отдельные ручные действия. Письма эти кнопки не отправляют, workflow рассылок и GAB 02 не изменяются.

## Установка

Под root на офисном сервере:

```bash
cd /opt/gab && git pull --ff-only && bash scripts/deploy-crm.sh
```

Это штатное обновление CRM с зашифрованным backup, проверками текущих контейнеров и откатом при ошибке. OCR пересобирать не требуется. Миграция `20261115_import_enrichment.sql` теперь явно включена в последовательность deploy: она создаёт недостающую таблицу, индексы и grants, не удаляя существующие записи. Прочие миграции остаются идемпотентными. Никакая кнопка подтверждения/отправки автоматически при установке не запускается.

Ранее настроенные `DADATA_API_KEY` и `CHECKO_API_KEY` из окружения контейнера сохраняются штатным deploy. Экран показывает наличие ключей, не их значения; правильность ключа/тариф проверяется первым запросом поставщику. Без доступного SSH/пароля sudo агент не может подтвердить их наличие на реальном сервере.

Если ключ отсутствует или его нужно заменить, выполните на сервере:

```bash
python3 scripts/configure-integrations.py
```

Скрипт спрашивает ключи скрытым вводом в Терминале; Enter сохраняет прежнее значение. Файл `/opt/gab-review-data/integrations.private.json` создаётся атомарно с правами 0600 и владельцем UID/GID процесса CRM. Через существующий bind mount он виден в контейнере как `/srv/gab-review-data/integrations.private.json`. Значения в этом файле имеют приоритет над окружением; читать их CRM будет при каждом запросе, перезапуск для ротации не нужен. Файл находится вне репозитория и дополнительно исключён из Git. Существующий зашифрованный backup каталога данных включает и его; закрытый AGE-ключ хранится отдельно. В API, аргументы процессов и вывод ключи не попадают.

## Поиск компаний и email

1. Нажмите «Найти компании и почты во всём пакете». Обрабатываются неподтверждённые строки всего документа, включая страницы таблицы за пределами текущего фильтра. Предел — 5000 строк, запросы идут последовательно. Можно остановиться после текущего запроса.
2. В DaData передаётся название или ИНН компании; в Checko — выбранный ИНН. Документ, полный OCR-текст, письмо и персональные вложения не отправляются. Запросы расходуют лимиты тарифа. [DaData ищет по названию, ИНН и ФИО ИП](https://dadata.ru/api/suggest/party/); наличие контактов зависит от ответа и тарифа. Checko использует существующие company/entrepreneur/finances endpoints.
3. При единственном кандидате можно сразу получить карточку Checko; при нескольких выберите компанию вручную и нажмите «Получить контакты выбранной компании». Сам поиск не подтверждает компанию и не создаёт инвестора. При ошибке поставщика/ключа/лимита поиск приостанавливается; автоматических повторов запросов нет.
4. Проверьте юридическое название, ИНН, регион, email, телефон и выручку. Отметьте «Проверил эту компанию; применить к строке», затем «Применить отмеченные компании и контакты». Для работы только с DaData снимите отметку запроса Checko; отдельная кнопка «Использовать данные DaData» позволяет выбрать его карточку. Дополнительные контакты DaData рядом с карточкой Checko показываются перед подтверждением и применяются только вместе с явной проверкой списка.
5. Флажок использования выручки Checko разрешает заменить распознанную выручку. Явные ручные исправления финансовых полей сохраняются. Источник и год остаются видны в строке. Смена компании/ИНН отзывает подтверждение её контактов; прежняя выручка Checko без ручных финансовых исправлений очищается до повторной проверки. История применения реестра хранится в аудите пакета.

Email поставщика привязан к компании, а не автоматически к физическому лицу из документа. Контакты DaData и Checko сохраняются с отдельными источниками и используются только после подтверждения выбранного ИНН. Контакты из файла не затираются. Если контактов нет в доступных источниках, система не выдумывает адреса.

## Кнопка «Подтвердить все»

1. Нажмите «Проверить все перед переносом». Будут показаны строки, email, готовность и причины блокировок; карточки CRM на этом шаге не создаются.
2. Проверьте список и поставьте отметку подтверждения. Строки с предупреждениями OCR требуют отдельной отметки проверки оригинала.
3. Нажмите «Подтвердить все готовые». Это явное ручное действие запускает перенос. Неполные финансовые данные, порог 100 млн ₽, неправильный ИНН и неоднозначные связи не обходятся; такие строки остаются для «Изменить»/«Совпадения».

Предпросмотр подписан сервером, ограничен пакетом и действует час. Изменения строк/контактов/совпадений требуют новой проверки. Новые однозначные связи с карточками, подтверждёнными в этом же пакете после предпросмотра, могут использоваться для следующих строк: это предотвращает создание нескольких карточек одной компании в массовом переносе. Финансовые и идентификационные проверки каждой строки сохраняются. Существующая логика переноса сохраняет проверки идентичности, версии, согласованности связей и объединяет только разрешённые поля. Одновременно подтверждать один пакет несколькими массовыми запросами нельзя; повтор уже подтверждённой строки не создаёт дубль. При обрыве часть строк может быть перенесена: обновите предпросмотр, уже перенесённые будут отмечены отдельно. Никакого восстановления отправки/переноса при обновлении страницы нет.

## Проверка

Внешние API и SMTP в тестах подменены, используются искусственные строки и отдельная схема PostgreSQL. Проверяются получение кандидатов без подтверждения, сбор контактов обоих источников, DaData без Checko, неверный ИНН ответа, устаревшая карточка/строка, сохранение ручной выручки, отзыв контактов после смены компании, предпросмотр без создания карточек, ручная отметка, предупреждения, финансовые блокировки, срок подписи/пакет, повтор и параллельные нажатия. Отдельно проверяются приватный файл ключей, отсутствие ключей в ответе конфигурации и JS-сценарии интерфейса.

Реальные API-ключи и тарифы на сервере нужно проверить после установки первым ручным поиском; локальные тесты этого не подтверждают.

Итоговый прогон: 93 Python-теста, 92 успешно, один локальный OCR-тест пропущен (Tesseract отсутствует). Проверка backup/restore выполнена настоящими PostgreSQL и age на искусственных данных. Прошли JS syntax, сценарии `test_import_actions_ui.js`, `test_import_progress_ui.js`, `test_import_workflow.js`, Python compile и shell syntax. Production не развёртывался; настоящие DaData/Checko запросы и отправка писем не выполнялись.

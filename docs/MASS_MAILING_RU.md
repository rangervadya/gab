# Ручная отправка выбранным инвесторам

## Проверенное подключение

Почтовый workflow `GABMailingFix20261116V2` («GAB — Mailing Test — Исправленная V2») опубликован. Он принимает одно письмо через защищённый webhook, подготавливает вложения, вызывает SMTP и возвращает `sent`, `to_email`, `mailing_id`, `accepted`, `rejected`, `message_id`. При аудите почтовый webhook не вызывался, письма не отправлялись.

Новый массовый запуск использует этот существующий однописьменный транспорт. Узлы, credentials, публикация и расписания n8n не меняются. При установке дополнительно проверяются именно опубликованный граф, единственный SMTP-узел без retry, адрес из `to_email`, отсутствие CC/BCC и наличие SMTP credential. Shared header token CRM сравнивается с Header Auth в памяти; значения не выводятся, не пишутся в файлы и не попадают в Git. SMTP credential для этой проверки остаётся зашифрованным. Соединение SMTP и почтовый webhook проверкой не вызываются.

## Установка без отправки

На сервере под root:

```bash
cd /opt/gab
git pull --ff-only
bash scripts/deploy-mailings.sh
```

Или предварительно только проверка:

```bash
bash scripts/deploy-mailings.sh --check
```

Этот entry point делает проверенный AGE backup, собирает и обновляет только CRM с сохранением Docker runtime-параметров и применяет аддитивные миграции, включая `20261119_bulk_mailing.sql`. GAB 02, почтовый workflow и остальные workflow не снимаются с публикации, не импортируются и не публикуются. Миграции и установка не запускают рассылку, не подтверждают импорт и не создают карточки инвесторов.

Применение миграции также доступно через общий deploy CRM/all; для этой задачи используйте специализированный `deploy-mailings.sh`. При выполняющейся почтовой отправке установка и откат блокируются. В конце должно быть `SUCCESS: mailings`. Архивы, AGE identity и инструкции отката — в [DEPLOY_OFFICE_RU.md](DEPLOY_OFFICE_RU.md).

## Как отправить самому

1. Загрузить и проверить инвесторов, вручную подтвердить перенос в CRM. Неподтверждённые строки автоматически получателями не становятся.
2. Открыть «Рассылки», выбрать или создать черновик. Заполнить тему, HTML/текст и вложения. Персонализация `{{contact_name}}` пока не реализована: такие шаблоны блокируют запуск.
3. В «GAB Invest → Инвесторы CRM» найти нужных инвесторов и отметить адреса. Кнопка «Выбрать найденные с email» выбирает только текущий показанный список; предел списка 5000. «Снять весь выбор CRM» очищает выбор CRM.
4. Нажать «Проверить перед отправкой». Текущий черновик и выбранные получатели сохранятся; появятся текст, вложения, точный список и число писем, а также причины исключений. Эта кнопка **не отправляет** письма.
5. Проверить данные, поставить отметку подтверждения и самому нажать «Отправить N писем». Только этот POST запускает работу. Каждому адресу отправляется отдельное письмо, без списка других получателей в To/CC/BCC.
6. Следить за счётчиками и результатом по каждому адресу. «Остановить после текущего письма» прекращает последующие попытки; уже начатое письмо отменить нельзя.

Не меняйте содержимое кампании после запуска: оно, вложения и список получателей блокируются. Для нового письма создайте новый черновик. Тестовое письмо на собственный адрес остаётся отдельной ручной кнопкой и не использует выбранных инвесторов.

## Защита от повторов и ограничения

- Требуются явное подтверждение и hash проверенного письма, вложений и адресов. Изменения после предпросмотра блокируют отправку.
- Одинаковые адреса нормализуются и исключаются; пустые, некорректные, уже обработанные и `opted_out` не отправляются. Отказ проверяется повторно непосредственно перед попыткой.
- Один процесс отправки на всю CRM, PostgreSQL advisory lock, уникальный run на кампанию и сохранённый request ID на каждый адрес. Двойное нажатие не запускает второй список.
- Перед сетевым вызовом состояние `sending` фиксируется в БД. Подтверждение засчитывается только для точных mailing ID и адреса с `sent=true`, наличием в SMTP `accepted` и отсутствием в `rejected`.
- Любой неподтверждённый результат/тайм-аут останавливает кампанию. Адрес получает `unknown`: SMTP мог принять письмо, поэтому повтор автоматически запрещён. Статус виден сотруднику; сверяйте его с почтовым сервером/журналом n8n.
- «Продолжить только неотправленные» — отдельное ручное действие. Оно пропускает `sent` и `unknown`; после обрыва процесса старые `sending` переводятся в `unknown`. При старте CRM, обновлении страницы и polling отправка не возобновляется.
- Отправка последовательная, интервал по умолчанию 3 секунды; `GAB_MAILING_INTERVAL_SECONDS` позволяет настроить паузу (не менее секунды). Ограничения SMTP-провайдера этим не отменяются; отказ останавливает обработку.
- Общий объём вложений — 8 МиБ, как в действующем n8n sender. Проверяются размер и SHA-256. При повреждении запуск/продолжение блокируется.
- `Принято SMTP` означает принятие сервером, а не гарантированное попадание во входящие. Не запускайте ручной retry того же письма из интерфейса n8n: он не использует CRM-защиту от повторов.
- Аудит хранит пользователя общей Basic Auth учётной записи, подтверждённый hash, ручные запуск/паузу/продолжение, request ID и SMTP message ID. Индивидуальные сотрудники при общей учётной записи не различаются.

## Проверки без писем

Тесты используют отдельную PostgreSQL schema и исключительно искусственные адреса `example.test`; функция доставки заменена. Проверяются предпросмотр без отправки, явное подтверждение, изменение hash, конкурентное двойное нажатие, пауза, тайм-аут, обрыв процесса, продолжение без повторов, отказы/некорректные адреса, повреждённые вложения, SMTP response contract и неизменность workflow при установке. Реальные SMTP и webhook не вызываются.

В локальном браузере проверены сохранение выбранного списка, предпросмотр тела и двух искусственных адресов, включение кнопки после отметки подтверждения. Кнопка отправки в браузере не нажималась; физическая доставка в локальном процессе дополнительно отключена.

Итог полного набора: 54 теста, 53 прошли, 1 локальный OCR-тест пропущен из-за отсутствия Tesseract на Mac. Дополнительно прошли Python compile, JavaScript/shell syntax и проверка diff. Реальных писем при разработке и проверках: 0.

- Перезапись исправлений повторным OCR: новые `manual_overrides` применяются триггером после каждого UPDATE. `raw_data` содержит последнее исходное извлечение, оригинал документа остаётся в файловом хранилище.

Не проверены: производственная схема и данные БД, рабочий Compose, запуск Docker-образов, Ollama, выполнение n8n. Адрес рабочего GAB 02 открывает страницу входа: https://n8n.techsmysl.ru/workflow/GAB02InvImp20261 . Доступа к авторизованной сессии нет. Исходный экспорт имел 27 узлов и `active: false`; текущая локальная версия содержит 24 узла, без трёх заменённых узлов Excel-нормализации. Значение в экспорте не доказывает состояние сервера.

## Форматы и пределы

| Формат | Обработчик | Ограничения |
|---|---|---|
| PDF | PyMuPDF; страницы со сканом/изображениями — Tesseract rus+eng | 200 страниц, до 40 млн пикселей на отрисованную страницу; шифрованные PDF отклоняются |
| DOCX | XML абзацев и таблиц | Физические страницы не определяются, изображения внутри Word не распознаются |
| DOC | antiword в Dockerfile OCR | Только текст; нужен реальный smoke test DOC в контейнере |
| XLSX | openpyxl, все листы | Формулы читаются из сохранённого кеша; отсутствующий кеш не вычисляется |
| XLS | xlrd, все листы | Не XLSB и не защищённые книги |
| CSV | csv, UTF-8/UTF-8 BOM или CP1251 | Запятая, точка с запятой, табуляция |
| JPG/JPEG/PNG | Pillow + Tesseract rus+eng | Текст распознаётся целиком, результат требует проверки |
| TIFF/TIF | Pillow, каждый кадр + Tesseract | До 200 логических страниц |
| PPTX | XML текстового слоя слайдов | Текст внутри изображений не распознаётся |

Загрузка: 20 МиБ на файл, расширение, MIME и сигнатура; OOXML — проверка контейнера, CRC и общего распакованного размера. Такая проверка не гарантирует семантическую целостность: повреждения отдельных форматов также выявляет обработчик. OCR-лимиты таблиц: 10000 строк на лист, 200 столбцов, 200 логических страниц и 2 млн символов. Таблицы делятся на порции с заголовком и номерами исходных строк, имя листа сохраняется в locator. OCR-предупреждения сохраняются и блокируют перенос до ручного решения.

Все извлечённые дополнительные поля сохраняются в `raw_data`. Ollama-схема включает адрес, сайт, отрасль, общие контакты, валюту, источник, статус финансовой проверки, тип инвестора и комментарии. Отдельных полей CRM для всех этих значений пока нет: они не переносятся автоматически в карточки. Нерублёвая выручка не используется для рублёвого порога.

## Работа сотрудника

1. Открыть «Импорт», выбрать несколько документов, загрузить. Файлы отправляются последовательно, с прогрессом и результатом каждого файла.
2. Обновить список для получения состояния обработки. Для пакета `failed` доступна кнопка повторной обработки; техническая причина сохраняется в пакете.
3. «Изменить» открывает форму на той же странице. Сохранение валидирует email, телефон, контрольную сумму ИНН, выручку и год. Отмена возвращает значения формы. История показывает автора, время, старое и новое значения.
4. При конфликте версии обновить строку и повторить правку. Подтверждённые и отклонённые строки закрыты для редактирования и повторной записи OCR.
5. «Совпадения» показывает кандидатов, источник, исправления, финансовую проверку и план. Можно выбрать кандидата или создание новой карточки. После выбора обязательно обновить план.
6. Поставить отдельные отметки разрешения допустимых предупреждений, проверить план и явно подтвердить перенос. Наличие совпадающего ИНН не позволяет создать вторую компанию. Чужой контакт и несовместимые связи инвестора отклоняются.
7. Финансовые ограничения, неверный ИНН и конфликтующие связи не обходятся отметками. Подтверждение использует транзакцию, row lock и advisory locks сильных идентификаторов; повтор возвращает прежний результат. Изменившийся план требует нового просмотра.

Существующие заполненные основные поля не перезаписываются; дополняются пустые поля и контакты в рамках явно подтверждённого плана. Предупреждения, решения и исправления фиксируются в событии подтверждения. Никакой отправки писем и автоматического подтверждения не добавлено.

## Обновление на сервере

Скрипты являются подготовкой для проверки оператором, а не доказательством production-готовности. В репозитории есть только Compose snippet OCR. Все имена сервисов и пути задаются явно и проверяются в полном серверном Compose.

Сначала проверить и зафиксировать изменения в Git, подготовить тестовое окружение, дождаться завершения выполняющихся GAB 02 и выключить только GAB 02. Не запускать старый экспорт с новым CRM: протокол записи требует worker token. Не менять workflow рассылок.

Задать переменные вне Git, например в защищённом окружении оператора:

- `EXPECTED_COMMIT` — полный проверенный commit на main, рабочая копия должна быть чистой.
- `COMPOSE_FILE` — абсолютный путь полного рабочего Compose.
- `CRM_SERVICE`, `OCR_SERVICE`, `POSTGRES_SERVICE`, `N8N_SERVICE` — реальные имена из `docker compose config --services`.
- `POSTGRES_USER` — роль для backup/миграции в `gab_crm`.
- `CRM_HEALTH_URL`, `OCR_HEALTH_URL` — доступные health URLs. `HEALTH_NETRC` — файл авторизации health CRM, если требуется; права 0600.
- `BACKUP_DIR` — каталог вне Git и вне каталогов, которые архивируются; `AGE_RECIPIENT` — публичный ключ age, приватный ключ хранить отдельно.
- `IMPORT_STORAGE` — фактический каталог оригиналов.
- `N8N_SETTINGS_DIR` — каталог n8n, включающий конфигурацию и encryption key. При внешнем ключе включить его защищённый файл в `CONFIG_DIR`.
- `CONFIG_DIR` — каталог настроек/секретов сервисов, включая env-файлы и все дополнительные Compose/env файлы. Скрипт не угадывает их расположение.

Порядок:

```bash
scripts/backup.sh
scripts/deploy-ocr.sh
scripts/deploy-crm.sh
# Только после остановки GAB 02 и окончания его выполнений:
# N8N_URL=https://n8n.techsmysl.ru и N8N_API_KEY задать в защищённом окружении
scripts/deploy-workflow.sh
```

Каждый deploy повторно делает backup. CRM применяет только новую миграцию `20261119_import_editor.sql` с `ON_ERROR_STOP`; существующие миграции должны уже быть установлены. Используется `up -d --no-deps --no-build` только выбранного сервиса. Остальные контейнеры не перезапускаются. Скрипт workflow обновляет только фиксированный ID GAB 02, проверяет, что он выключен, не активирует и не запускает его. Credential IDs в экспорте должны существовать на целевом n8n.

После обновления провести smoke tests всех форматов на искусственных документах, проверить версии образов и health, затем включить и запустить только GAB 02. Не выполнять production-развёртывание до отдельного согласования.

## Backup и восстановление

`backup.sh` создаёт age-зашифрованный tar с pg_dump custom-format `gab_crm`, workflow export, зашифрованными n8n credentials, конфигурацией, ключом n8n, оригиналами и образами CRM/OCR (если их сервисы заданы). Без ключа n8n credentials нельзя восстановить; архив age также требует отдельного приватного ключа. Дамп и файлы собираются последовательно: для согласованного disaster recovery остановить приём загрузок/изменений и дождаться окончания импорта на время backup. Автоматической остановки всего Compose нет.

Проверять расшифровку и `pg_restore --list` в изолированной среде, хранить копии вне сервера с отдельным управлением ключами. Скрипт не настраивает расписание, ротацию и внешнее хранилище.

Для отката образа задать `BACKUP_ARCHIVE`, `AGE_IDENTITY`, `ROLLBACK_COMPONENT=crm` или `ocr`, а также переменные backup и Compose; выполнить `scripts/rollback.sh`. Он сначала создаст новую копию, загрузит прежний образ, заменит только выбранный сервис и проверит health. Новая миграция аддитивная; данные и аудит при откате образа не удаляются.

Восстановление данных выполняется отдельно с согласованным окном обслуживания:

1. Расшифровать доверенный архив в защищённый временный каталог, проверить checksum и commit.
2. Развернуть дамп в новую отдельную БД `pg_restore --exit-on-error`, проверить таблицы и количество записей.
3. Восстановить `state.tar.gz` в изолированный каталог: архив содержит пути без начального `/`. Сопоставить их с реальными серверными каталогами, не распаковывать сразу поверх production.
4. Восстановить оригиналы и конфигурацию с исходными владельцами/правами. Восстановить n8n encryption key до импорта credentials; workflows восстанавливать в выключенном состоянии, рассылки не запускать.
5. Проверить на искусственных данных, переключить сервисы после отдельного согласования и проверить health. Старую БД и документы сохранить до проверки.

`.gitignore` исключает env, ключи, дампы, backups, uploads, credentials. Уже отслеживаемые файлы правило не удаляет. В исходном репозитории уже отслеживаются `data/records.json` и `data/data_quality_report.json`; README указывает на реальные исходные контактные данные. Их содержимое здесь не использовалось для тестов. Нужен отдельный аудит истории Git и решение владельца по ранее опубликованным данным; история не переписывалась.
